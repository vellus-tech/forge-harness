# Tasks — extend-kb-corpus-sources

> Tasks do change `extend-kb-corpus-sources`, ordenadas por dependência. Formato de ID: `TASK-NN` (numeração contínua).
> Status: `[ ]` todo · `[-]` em progresso · `[X]` concluída · `[!]` bloqueada (exige intervenção humana).
> Gate único deste change: `tests/extend-kb-corpus-sources-gate.sh`, com grupos de cenário numerados continuamente (`[1]`, `[2]`, ... `FAIL [n] <motivo>`), no mesmo padrão `shell-gate` que `red-classify.mjs` reconhece (`^FAIL \[[^\]\n]+\]`) — cada TASK adiciona seus casos ao MESMO arquivo, nunca cria gate próprio.
> Cada task é atômica (commit de vermelho + commit de implementação), rastreável a REQ/design, e declara `Teste (comando)` + `Padrão de falha` (+ `Setup do teste`, quando precisa de algo além de `bash`/`node`).
> Convenção do dogfood: maquinaria executável vive em `template/.forge/`; todo comando de teste roda da raiz do repositório, nunca com `cd template`.
> Toda TASK cujo critério de aceite não tenha prova automatizada aqui é, por definição, incompleta (achado do `yolo-gate` no gate `tasks_reviewed`, iteração 1: rastreabilidade nominal REQ→TASK não basta — cada critério precisa de caso de teste).
