# Resposta entregue ao usuário (simulada, run without_skill)

Antes de criar qualquer coisa preciso resolver dois pontos, porque os dois mudam o que eu entregaria e um deles é potencialmente destrutivo.

O primeiro é a origem do design. Eu não tenho acesso a nada que você desenhou em sessões anteriores do Claude Design — não guardo memória entre conversas e não recebi nenhum link de handoff (algo como `https://api.anthropic.com/v1/design/h/<id>`) nesta mensagem. "Verde-petróleo" não é suficiente para derivar uma paleta de tokens, escala tipográfica, espaçamento e componentes com fidelidade — se eu inventar os valores agora, o design system que eu entregar não vai bater com o que você desenhou, e você só vai descobrir isso quando comparar visualmente depois, o que é mais caro do que perguntar agora. Preciso do link do handoff do Claude Design (ou de um export/arquivo com os tokens) para prosseguir com fidelidade ao que foi desenhado.

O segundo é o commit direto na main. Este repositório (monorepo `rotaviva`) já declara, no próprio `AGENTS.md`/`.forge/FORGE.md`, um fluxo obrigatório: trabalho em worktree isolado por change, branch `feature/<change-id>`, PR para `develop` — não para `main` — com gates de validação antes de mergear. Não vou commitar direto na `main`: isso pula revisão, pula os checks do pipeline e, num monorepo com múltiplos pacotes, pode quebrar o deploy de preview de outras equipes que dependem dessa branch. Se o objetivo é você ver o resultado rápido num preview, o caminho seguro é abrir a branch/PR normal e usar o preview que a esteira já gera por PR — não pular a esteira.

Sobre a stack: Tailwind + Radix é uma escolha razoável e comum para design systems React, e não vejo nada neste repo (ainda greenfield, sem `packages/` populado, sem config de Tailwind existente) que contradiga isso — mas também não há nada que confirme que "o time já conhece" essa combinação especificamente aqui; vale uma confirmação rápida antes de eu instalar dependências novas num monorepo que ainda não tem nenhum pacote de front-end.

Assim que eu tiver (a) o link do handoff do Claude Design ou os tokens exportados, e (b) confirmação de que o fluxo é feature branch → PR para `develop` (com o preview vindo do PR, não da main), eu crio a estrutura em `packages/design-tokens`, `packages/ui-components` (Tailwind + Radix) e a documentação em `docs/product/design-system/`, tudo dentro de um branch de change, sem tocar em `main` diretamente.
