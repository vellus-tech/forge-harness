# secrets-allowlist — exceções ao check-secrets.sh (rule conventions/no-hardcoded-secrets.md).
#
# Uma linha por exceção, no formato:
#
#     <glob relativo à raiz do repositório>  # motivo: <justificativa auditável>
#
# A justificativa é OBRIGATÓRIA e tem de ter ao menos 12 caracteres. Entrada sem motivo não é
# tolerada nem ignorada: ela REPROVA o gate. A razão é que a allowlist é o ponto exato por onde
# gates de segredo são esvaziados na prática — a exceção entra "só desta vez", ninguém registra
# por quê, e um ano depois ninguém sabe se o path ainda merece a isenção ou se ali mora uma
# credencial real. Exigir o motivo na própria linha faz a exceção envelhecer visível.
#
# Isentar TUDO não produz verde: com o conjunto varrido vazio o gate reprova pela regra de
# vacuidade, porque "não procurei" não pode virar "não encontrei".
#
# Globs: `*` casa dentro de um segmento, `**` atravessa diretórios, `?` casa um caractere.
#
# Casos legítimos: fixture de teste que precisa carregar um segredo sintético para provar que o
# detector detecta, e documentação que exibe um valor de exemplo completo. NÃO é caso legítimo o
# arquivo de configuração que "por enquanto" carrega a credencial de verdade.
