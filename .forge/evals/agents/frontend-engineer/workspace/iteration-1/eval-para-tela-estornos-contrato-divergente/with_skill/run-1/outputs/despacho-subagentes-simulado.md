# Despacho de subagentes (simulado, não executado)

A tarefa proibiu spawnar subagentes de fato. Nenhum subagente seria necessário para este caso: a divergência contratual foi identificada por leitura direta dos artefatos (contrato, design.md, tasks.md, código do backend) na rotina obrigatória do agente frontend-engineer (§4), sem necessidade de investigação paralela ou implementação multi-arquivo.

Se a tarefa tivesse prosseguido (hipótese descartada, pois a implementação foi bloqueada pela divergência):

- Nenhum despacho a `task-coder` seria emitido, pois o bloqueio ocorre antes da fase de implementação — o próprio frontend-engineer, seguindo §26, para e sinaliza em vez de delegar a escrita de código sobre um requisito contraditório.
- Uma eventual reconciliação de `tasks.md` seria trabalho do dono do módulo (produto/Pagamentos), não uma TASK a redespachar para outro agente de código.
